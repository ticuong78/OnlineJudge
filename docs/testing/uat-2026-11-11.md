Branch `feat/oj-12-i18n-en-vi`. Run on a throwaway stack (test containers on 55432/56379, fresh database `oj_uat`,
seed data, real engine with the Docker sandbox). The development database was not used.

**Status 2026-11-12:**
- Every finding below is fixed under spec `docs/specs/OJ-13-uat-fixes.md`.
- Each fix was re-checked on a fresh UAT stack in Chromium, at the widths where it was found.
- Follow-up sweeps found no remaining sideways scroll, unlabelled controls or targets under 24px on the teacher and
  student pages, and every page now has its own tab title.

## Findings

Severity: **High** loses user work or blocks a task; **Medium** hurts a common flow or accessibility; **Low** polish.

### High

**H1. Unsaved teacher work is lost without warning.** On `/bank/problems/new` I filled title, statement, tag and a
test, then clicked "Ngân hàng" in the header: the page changed with no prompt, and Back showed an empty form. There is
no `beforeunload` or route guard anywhere in the frontend and no draft for the problem or set editors (student code
drafts are saved, teacher forms are not). Same risk on `/bank/sets/new`, `/bank/sets/[id]/edit` and the problem detail
page, which also has two separate saves ("Lưu bài", "Lưu test").

### Medium

**M1. Phone: the verdict is off screen after Submit.** At 375 px the result panel renders under the 487 px editor
(about y=1700 while the student is looking at the editor). The panel is good once found (score, tests, time, memory,
"next problem"), and it is an `aria-live` region, but sighted students see nothing change. Desktop docks it under the
editor and is fine.

**M2. Phone and tablet: the exam countdown scrolls away.** On a timed session's problem page the timer is only in the
top bar; scrolled to the editor it sits at -613 px. Desktop keeps it visible. The sticky toolbar with the language
picker and Submit is the natural place for it.

**M3. Phone: the editor traps scrolling.** The editor is full width, so a swipe or wheel over it scrolls the code, not
the page; there is almost no area left to scroll the page past it. Monaco's `scrollbar.alwaysConsumeMouseWheel: false`
and a shorter editor on small screens would help.

**M4. Header wraps at 1280 to 1319 px for teachers in an organization.** With 7 menu items, "Online Judge" and the
teacher's name each break onto two lines (measured: brand 48 px, name 40 px high; 24 and 20 from 1320 px). Same in
English. A longer name widens the band. 1280 is a common laptop width.

**M5. Dialogs do not manage focus.** The shared `Modal` (`components/ui.tsx`) has `role="dialog"` and Escape, but does
not move focus into the dialog, trap Tab, return focus to the trigger, or set `aria-labelledby`. Checked on the
"start timed exam" confirmation with a focused trigger. Affects every dialog: start exam, assign, ask a question,
confirm delete, create class.

**M6. Form errors are not announced.** `InlineAlert` renders a plain `div`, so "Email hoặc mật khẩu không đúng." and
dialog errors are silent for screen readers. `role="alert"` (errors) or `role="status"` (notices) fixes all of them.

**M7. Asking a question mid-exam leaves the problem.** "Hỏi về bài này" on a timed exam problem posts the question and
navigates to the thread page, whose back link goes to the class, not the problem. The student then has to find their
way back while the clock runs. Stay on the problem with a confirmation, or make the back link return to the origin.

**M8. Teachers are not told about new questions.** The teacher home shows join requests and integrity flags but not
unanswered questions; the UAT question was only visible inside the class.

**M9. Every page has the same tab title "Online Judge".** Only the print pages set their own. Tabs, history and screen
reader page announcements cannot tell pages apart.

### Low

- **L1. Unlabelled controls:**
  - `MarkdownField` textareas (statement sections, replies, session instructions), whose label is a `span`, plus the
    Write/Preview toggle, which has no `aria-pressed`.
  - Test input/output textareas in the test editor.
  - Search fields in the bank, sets and admin users pages, which have a placeholder only.
  - The code language `select`, read as "C++17".
  - The logo link when its text is hidden, which has no name.
- **L2. Small touch targets on phones (under 24 px):**
  - Delete-test buttons, 12×12.
  - AI suggestion switches, 36×20.
  - "Sao chép" (Copy), 61×20.
  - "Hỏi về bài này" (Ask about this problem), 20 px high.
- **L3. "Giao bài" is offered for a problem with no tests.** The refusal ("Bài P0010 chưa có test…") only appears after the teacher fills the assign form.
- **L4. Required-field validation uses the browser bubble, in the browser's language.** It showed "Please fill out this field." on a Vietnamese page.
- **L5. Sign-out keeps `?next=` pointing at the previous user's page.** The next person to sign in on that device is sent there.
- **L6. Mobile menu focus.** Escape closes the menu, but focus does not return to the Menu button.
- **L7. The timed session page lists the rules twice.** They appear as header chips and again as bullets.
- **L8. Teachers see a student progress line on their own session page.** "Đã giải 0/1, 0/100 điểm".
- **L9. AI switches are shown when the server has no Claude key.** The toast explains it, but the switches could be disabled with the reason.
- **L10. "Tạo lớp đầu tiên" needs a second click.** It opens the Classes page, where the teacher clicks "Tạo lớp" again.

## Not covered

- Real phones and Safari. The pass used Chromium with device emulation.
- Screen-reader testing with VoiceOver or NVDA. Accessibility was checked from the DOM.
- AI features with a real Claude key, and document import with real `.docx` / `.pdf` files.
- The print layout on paper.
- Organization admin actions beyond viewing: inviting or removing teachers, and seats.
- Performance under load. The dev server was used. The doubled API calls seen in the network log come from React's development mode.
