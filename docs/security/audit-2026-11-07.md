## Sandbox floor (CLAUDE.md security rule 5)

The new design is at least as strong as the old floor. The container no longer runs with `--user 65534`; instead it runs as root holding only SETUID, SETGID and KILL. It also adds `--read-only`, tmpfs `/box` and `/tmp`, `--init`, and removes the host bind mount. `oj-run` drops to 65534 before untrusted code runs.

The verifier checked live:
- The child runs as `uid=65534 gid=65534` with CapPrm, CapEff and CapAmb all 0, `NoNewPrivs: 1` and `Seccomp: 2`.
- From user 65534, `kill -9 1` and signals to every root process fail with EPERM.
- Every untrusted path (compile and run) goes through `supervise()` with a `--` separator. `oj-run` refuses uid or gid 0.
- The source-file write cannot be abused: the name is regex-checked and passed as a positional argument, and the write happens before any untrusted process exists.
- Argument parsing in `oj-run.c` is bounds-checked.

Residual risk: Docker itself no longer enforces uid 65534. Any future exec path that bypasses `oj-run` would run as container root, though still under no-new-privileges, seccomp, no network and a read-only root. Recorded in ADR 0004.
